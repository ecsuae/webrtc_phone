# Push Notifications for Incoming Calls - Quick Reference

## Problem
WebRTC browsers cannot receive incoming calls when the tab is closed or inactive.

## Solution
Web Push Notifications + Service Worker to wake up the browser when a call arrives.

## Docker-Based Setup (Recommended)

The push notification server is now fully Dockerized and included in the main `docker-compose.yml`.

### Files Structure

```
/opt/webrtc-sbc/
├── www/
│   ├── sw.js                     # Service Worker (handles push)
│   ├── manifest.json             # PWA manifest
│   └── app/
│       └── push.js               # Push notification module
│
├── push-server/
│   ├── server.js                 # Push notification server
│   ├── package.json              # Dependencies
│   ├── Dockerfile                # Docker image definition
│   ├── .dockerignore             # Docker build exclusions
│   ├── generate-keys.js          # VAPID key generator
│   └── README.md                 # Server documentation
│
├── docker-compose.yml            # All services including push-server
├── .env                          # Configuration (includes VAPID keys)
└── scripts/
    └── setup.sh                  # Automated setup script
```

## Quick Setup (Fully Automated)

```bash
# 1. Run setup script (generates VAPID keys automatically)
./scripts/setup.sh

# 2. Edit .env file with your domain and IPs
nano .env

# 3. Start all services (push-server included)
docker-compose up -d

# 4. Verify push server is running
docker logs push-server
curl http://localhost:3001/health
```

That's it! The push notification server is now running as a Docker container.
## Docker Management

```bash
# View push-server logs
docker logs push-server -f

# Restart push-server only
docker restart push-server

# Rebuild push-server after code changes
docker-compose build push-server
docker-compose up -d push-server

# Check health status
curl http://localhost:3001/health

# Or use Makefile
make rebuild-push

```

## Configuration

All push server configuration is in the main `.env` file:

```bash
# Push Notification Server
VAPID_PUBLIC_KEY=B...    # Auto-generated by setup.sh
VAPID_PRIVATE_KEY=...     # Auto-generated by setup.sh
VAPID_SUBJECT=mailto:admin@example.com
```

The setup script (`./scripts/setup.sh`) automatically:
1. Generates new VAPID keys
2. Updates `.env` file
3. Updates `www/app/push.js` with public key

## Integration Points

### 1. Web App
- Service worker registers on page load
- Subscribes to push when user registers (automatic)
- Handles notification clicks (answer/reject)

### 2. Nginx
- Proxies `/api/push/` to push server (Docker host network mode)
- Serves service worker with correct headers

### 3. Kamailio (Coming Next)
- Will call push API when routing to WebRTC client
- Passes extension, caller ID, and call ID

### 4. FreeSWITCH (optional)
- Can trigger push from dialplan
- Or use Lua script for advanced logic

## Troubleshooting

**Push server not starting?**
```bash
# Check logs
docker logs push-server

# Verify VAPID keys in .env
grep VAPID .env

# Rebuild container
docker-compose build push-server
docker-compose up -d push-server
```

**No notifications?**
- Check browser console for errors
- Verify VAPID key is configured in `www/app/push.js`
- Check push server is running: `curl http://localhost:3001/health`
- Verify subscription: `curl http://localhost:3001/api/push/subscriptions`
- Test notification permission is granted in browser

**iOS not working?**
- Must be iOS 16.4 or newer
- Must install as PWA ("Add to Home Screen")
- Or consider native app wrapper

**Docker container keeps restarting?**
```bash
# Check for missing environment variables
docker logs push-server

# Verify .env has all required variables
grep -E "VAPID|PORT" .env

# Test manually
docker run --rm -it --env-file .env webrtc-sbc-push-server
```

## Migration from PM2 to Docker

If you previously installed with PM2, clean it up:

```bash
# Stop and remove PM2 process
pm2 stop webrtc-push
pm2 delete webrtc-push
pm2 save

# Remove PM2 startup script (optional)
pm2 unstartup

# Now use Docker
docker-compose up -d push-server
```
