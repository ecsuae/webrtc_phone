# WebRTC SBC - Quick Start Guide

## 🎯 Zero to Running in 5 Minutes

This is truly **plug-and-play**. Follow these steps to get your WebRTC SBC running:

### Prerequisites
- Linux server with Docker and Docker Compose installed
- SSL certificates (Let's Encrypt)
- Open firewall ports (443, 80, 5060, 3478, 5349, 30000-31000, 49160-49200)

---

## 📦 Installation

### Step 1: Clone Repository
```bash
git clone <your-repo-url> /opt/webrtc-sbc
cd /opt/webrtc-sbc
```

### Step 2: Run Setup Script
```bash
./scripts/setup.sh
```
This will:
- Create `.env` from template
- Generate VAPID keys for push notifications
- Update configuration files

### Step 3: Edit Configuration
```bash
nano .env
```

**Required changes:**
```bash
DOMAIN=phone.example.com        # Your domain
PUBLIC_IP=1.2.3.4              # Your server's public IP
PBX_IP=pbx.example.com         # Your PBX IP/domain
PBX_PORT=5060                  # PBX SIP port
TURN_USER=turnuser             # TURN username (change this)
TURN_PASS=secure_password      # TURN password (change this)
VAPID_SUBJECT=mailto:admin@example.com  # Your contact email
```

**Note:** VAPID keys are auto-generated by setup script. Don't change them unless regenerating.

### Step 4: Place SSL Certificates
```bash
# Copy your certificates to the certs directory
cp /path/to/fullchain.pem ./certs/
cp /path/to/privkey.pem ./certs/
```

### Step 5: Start Services
```bash
docker-compose up -d
```

### Step 6: Verify Everything is Running
```bash
docker-compose ps
```

You should see all services with status "Up":
- coturn
- rtpengine
- kamailio
- push-server (healthy)
- phone-nginx

## 🔥 Troubleshooting

### Push Server Not Starting

**Check logs:**
```bash
docker logs push-server
```

**Common issues:**
- Missing VAPID keys in `.env`
- Port 3001 already in use
- Invalid environment variables

**Solution:**
```bash
# Regenerate VAPID keys
cd push-server
node generate-keys.js

# Copy output to .env
nano ../.env
```

### WebSocket Connection Failed

**Check Nginx:**
```bash
docker logs phone-nginx
```

**Verify SSL certificates:**
```bash
ls -l certs/
# Should show: fullchain.pem, privkey.pem
```

### Cannot Register to PBX

**Check Kamailio connectivity:**
```bash
docker logs kamailio | grep -i error
```

**Verify PBX accepts SIP from your server:**
- Check PBX firewall/ACL rules
- Ensure port 5060 UDP is open

### Push Notifications Not Working

**Browser must be HTTPS:**
- Push notifications only work over HTTPS
- Localhost/http:// will not work in production

**Check browser console:**
- Open DevTools (F12)
- Look for push-related errors
- Verify notification permission is granted

**Test manually:**
```bash
# 1. Check push server
curl http://localhost:3001/health

# 2. Check subscriptions (after browser registers)
curl http://localhost:3001/api/push/subscriptions | jq

# 3. Send test notification
curl -X POST http://localhost:3001/api/push/notify \
  -H "Content-Type: application/json" \
  -d '{"extension":"YOUR_EXTENSION","from":"Test","title":"Test Call"}' | jq
```

## 🌐 Migration to New Server

Moving to a new server is simple:

### On Old Server:
```bash
cd /opt/webrtc-sbc
tar -czf webrtc-backup.tar.gz .env certs/
```

### On New Server:
```bash
# Clone repo
git clone <your-repo> /opt/webrtc-sbc
cd /opt/webrtc-sbc

# Restore backup
tar -xzf webrtc-backup.tar.gz

# Update IP addresses
nano .env
# Change: PUBLIC_IP, PBX_IP (if needed)

# Start services
docker-compose up -d
```

That's it! Zero interaction required beyond updating IPs.

## 📋 Port Checklist

Make sure these ports are open in your firewall:

**Required:**
- ✅ 443 (TCP) - HTTPS + WebSocket
- ✅ 80 (TCP) - HTTP redirect
- ✅ 5060 (UDP) - SIP to PBX
- ✅ 3478 (UDP) - TURN server
- ✅ 5349 (TCP) - TURN over TLS

**RTP Media:**
- ✅ 30000-31000 (UDP) - RTPEngine
- ✅ 49160-49200 (UDP) - COTURN relay

**Test ports:**
```bash
# Check if ports are listening
ss -tulpn | grep -E ':(443|80|5060|3478|5349)'

# Check from external machine
nc -zv your-server-ip 443
nc -zu your-server-ip 5060
```
